# 饭搭子｜维护与更新说明

## 当前状态

- 项目已完成当前阶段的功能、视觉验收、质量检查、GitHub 发布和 Vercel 部署。
- 用户日常只需要打开 Vercel 提供的网页地址使用，不需要终端。
- GitHub：<https://github.com/zhangyangyinglu/fandazi>

## 以后怎么提需求

用户直接在 Codex 对话中描述问题即可，例如：

- “计划页的调整计划按钮又没有反应。”
- “我想增加一个家庭成员入口。”
- “这个页面在手机上显示不对。”

Codex 会按以下顺序处理：复现问题 → 修改代码 → 测试和构建 → 提交到 GitHub → 由 Vercel 自动更新线上版本 → 请用户验收。

## 更新后是否需要重新部署

需要，但通常是自动完成的：

1. Codex 将修改后的代码推送到 GitHub `main` 分支。
2. Vercel 监听到 `main` 的新提交。
3. Vercel 自动构建并发布新版本。
4. 用户刷新网页即可看到更新。

如果自动部署失败，再进入 Vercel 项目的 Deployments 页面点击 Redeploy；不需要安装编码代理插件。

## AI Key 和数据边界

- AI Key 在饭搭子页面内由用户自己配置，不发送给 Codex，不提交到 GitHub。
- 基础功能不需要 AI Key。
- 默认数据保存在当前浏览器；家庭同步属于可选配置。
- 不要把 API Key、PAT、Supabase service role key 发到聊天或提交到仓库。

## 遇到问题时提供什么

直接告诉 Codex：页面地址、操作步骤、实际结果、期望结果；如果方便，附截图。不要附带任何 Key 或密码。

## 回滚原则

如果更新后出现问题，优先回到 Vercel 的上一条成功部署；同时保留 GitHub 提交记录，修复后再重新发布。
